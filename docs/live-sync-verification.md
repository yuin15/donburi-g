# 任意Liveの同期・期限・後始末

2026-09-12 / #7、#8、#9、#11。実APIを使わず検証可能な通信・制御の不足を補完。通常CPU対戦は変更しない。LiveClientと実行時スキーマを動的importへ分け、CPU入口では読み込まない。

- 2つのMatchSessionを60秒進め、別の試合ID・改造・字幕・イベント・停止対象が混線しないこと、双方30回転、各試合の判断呼び出し2回を確認。
- 同じcommandIdの再送、別試合への操作、不正な改造ID、得点変更メッセージを拒否。プレイヤーとAIの返答がタイマー停止中に期限を超えて届いても受付を延長しない。
- 全サーバー出力をクライアントの実行時スキーマへ通し、連番・時刻・IDを照合。最終回のイベント欠落から最後の確定絵柄と得点を含むsnapshotで回復し、重複で二重更新しない。
- 5秒以内に同期が回復しなければマイク・映像・WebSocketを解放して中断。ページの非表示からは同一接続へsnapshotを要求。別試合への自動切替はしない。
- 1秒あたりのメッセージ数と音声文字数、個別メッセージ、セッション時間を制限。無応答・終了・多重終了・開始途中の取消は既存の解放テストと併せて確認。
- 重要イベントの発話候補をラウンド・期限・得点の前提・優先度で選別。通常の自発的な要求は5回まで、確定結果の1回を予約。終了・会話停止・別試合で候補が混ざらない。

検証は実装されたサーバー/クライアントを動かし、外部プロバイダーとマイク・ソケットをテスト代替物にしたもの。実際のVercel有料接続、発声時刻、音声の割り込み、残存するプロバイダーセッション、実測費用を確認した結果ではない。これらは #3 / #8 / #9 / #11 に残す。`LIVE_MODE_ENABLED=false` を維持する。

詳細な形式・復旧・上限は [protocol.md](protocol.md)。ビジュアルと無料CPU対戦は [visual-redesign-verification.md](visual-redesign-verification.md)。

## 接続初期化・会話文脈の追加修正 (#47 / #48)

- WebSocketのclose/errorを認証拒否・非同期の枠取得より前から監視。拒否直後の過大フレーム、認証待機中の切断・エラー、初期化と終了の競合で未処理例外を出さず、取得枠を一度だけ返す。実localhost WebSocketと代替MatchSessionによる9ケースを追加した。
- GPTへ渡す文脈を整数秒・得点・確定改造・終了状態の変化時に更新。マイク音声を渡す前にもドメインを追いつかせ、最新の確定情報を先に送る。通常当たりでも更新し、同じ文脈を100msごとに再送しない。5ケースを追加した。
- 再現seed `0x01000000` では15秒時点1,680対0・残り45秒。修正前は会話文脈が1,440対0・残り52秒で止まっていた。修正後は最新値を渡す。これはプロバイダーを代替した制御テストであり、実際の発声精度の証明ではない。

この時点ではGPT-Liveの音声deltaに生成IDや完了イベントがなく、終了interrupt後の旧delta混入が未解決だった。#58で接続世代を分ける修正を追加した（下記）。指示受理ACKを音声停止完了と同一視しない。

## 直近の出目と配当 (#54)

会話文脈に、両者の直近の確定回転番号・3絵柄・配当を追加。開始前は未回転と明示する。遅れたtickが複数回転を処理した場合も、最新spinを確定得点とそろえてから文脈を送る。未来の出目や保留中の改造は含めない。

既存4テストを強化し、修正前に出目情報の検査が失敗することを確認した。14秒の通常ベル当たり、24.1秒への追いつき、最終30回転について、当該spinの情報がマイク送信より先に渡る。15秒までの文脈送信は従来どおり17回で、発話要求を増やしていない。関連22テスト成功。実プロバイダーの回答精度は未確認。

## 実WebSocketとMatchSessionの結合 (#55)

`api/ws.integration.test.ts` はlocalhostの実HTTP/WebSocketサーバーと本物のMatchSessionを結合する。認証の成功応答・設定・利用枠と、外部GPT/LiveAvatar/判断を代替し、認証自体や外部プロバイダーの成立を主張しない。外部fetchが発生したら失敗する。

通常接続と途中の音声終了の2ケースで、hello→ready→start→改造2回→30回転の結果→最新snapshot再取得→closeを確認した。両者の得点・statsが実際に届いた30回転分と一致し、全出力がwireスキーマに適合、連番・試合IDが一貫している。音声を終了しても同じゲーム接続が続き、最終終了で利用枠・各媒体を一度だけ解放する。

Date.nowだけを進め、実タイマー/I/Oを動かしたままping/pongで送信処理の境界を確認する。親への統合後は2ケース128ms、全165テスト・型検査・lint・Node ESM起動/拒否応答・本番ビルドが成功した。Vercel上の認証済み画面や実音声の通し試験は #7/#3 に残る。

## 結果音声を接続世代で分離 (#58)

試合中のGPT接続を無効化して閉じ、LiveAvatarの `agent.audio_buffer_cleared.source_event_id` と自分が送ったinterruptのUUIDが一致してから、結果専用GPT接続を1回だけ開始する。以前の接続から遅れて届く音声・字幕・ready・errorは転送しない。失敗時は音声を終了し、確定結果を保持する。

結果用の初期instructionsには確定得点・勝者・30回目の出目と配当・改造を含める。最近のユーザー発言は最大300文字の未信頼データとして一時的に引き継ぎ、保存・ログ出力しない。試合終了と同時にクライアントのマイクを止め、結果用GPTへはサーバーからPCM16/24kHz/monoの100ms無音を100ms間隔で渡す。1試合最大2GPT接続・1LiveAvatarとし、結果から8秒または初期化から120秒の早い方を終了期限にする。

期限は転送callbackでも判定するため、タイマーが遅延しても期限後の音声・字幕は渡らない。120秒は終了処理の開始期限であり、遠隔セッションや課金の終了時刻を保証しない。closeイベントと実サービスの利用量は別に確認する。

検証は全190テスト成功（従来165から25件追加）。MatchSession28、MediaServerLeg15、LiveClient15、GptLiveBridge6、実localhost WebSocket結合2ケースを含む。ACKと旧closeの到着順、誤ACK・無応答・遅着・途中切断、早すぎる出力、旧出力、120秒と8秒の期限、無音データと停止、両世代のusage保持を確認した。型検査・lint・生成済みNode ESM起動/拒否応答・本番ビルドも成功。

ブラウザのDEV検収では試合中字幕→結果snapshot→結果字幕前半→重複match_ended/snapshot→字幕後半の順を通し、連結結果が「検収字幕: いい勝負だったね。」だけになることを確認した。正常終了後も保持し、失敗では静的な結果台詞へ戻り、再戦準備では0点・60秒・内訳0行に初期化する。[表示4ケース](evidence/result-voice/ui-cases.json)、[1280×720](evidence/result-voice/caption-1280.webp)、[1920×1080](evidence/result-voice/caption-1920.webp)。

設計の根拠は[OpenAIのセッション管理](https://developers.openai.com/api/docs/guides/live-conversations)と[LiveAvatar LITEイベント](https://docs.liveavatar.com/docs/lite-mode/events)。音声deltaに応答ID/音声完了境界がないため、指示ACKを旧音声終了とは扱わない。LiveAvatarのACKも既にブラウザへ届いた再生バッファの消去を証明しない。実際の発声・聞こえる中断・口同期・遅延・残存セッションは引き続き #3/#8/#11 に残す。実APIは未使用、公開Liveは無効。
