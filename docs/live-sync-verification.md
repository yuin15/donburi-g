# 任意Liveの同期・期限・後始末

2026-09-12 / #7、#8、#9、#11。実APIを使わず検証可能な通信・制御の不足を補完。通常CPU対戦は変更しない。LiveClientと実行時スキーマを動的importへ分け、CPU入口では読み込まない。

- 2つのMatchSessionを60秒進め、別の試合ID・改造・字幕・イベント・停止対象が混線しないこと、双方30回転、各試合の判断呼び出し2回を確認。
- 同じcommandIdの再送、別試合への操作、不正な改造ID、得点変更メッセージを拒否。プレイヤーとAIの返答がタイマー停止中に期限を超えて届いても受付を延長しない。
- 全サーバー出力をクライアントの実行時スキーマへ通し、連番・時刻・IDを照合。最終回のイベント欠落から最後の確定絵柄と得点を含むsnapshotで回復し、重複で二重更新しない。
- 5秒以内に同期が回復しなければマイク・映像・WebSocketを解放して中断。ページの非表示からは同一接続へsnapshotを要求。別試合への自動切替はしない。
- 1秒あたりのメッセージ数と音声文字数、個別メッセージ、セッション時間を制限。無応答・終了・多重終了・開始途中の取消は既存の解放テストと併せて確認。
- 重要イベントの発話候補をラウンド・期限・得点の前提・優先度で選別。通常の自発的な要求は5回まで、確定結果の1回を予約。終了・会話停止・別試合で候補が混ざらない。

検証は実装されたサーバー/クライアントを動かし、外部プロバイダーとマイク・ソケットをテスト代替物にしたもの。実際のVercel有料接続、発声時刻、音声の割り込み、残存するプロバイダーセッション、実測費用を確認した結果ではない。これらは #3 / #8 / #9 / #11 に残す。`LIVE_MODE_ENABLED=false` を維持する。

詳細な形式・復旧・上限は [protocol.md](protocol.md)。ビジュアルと無料CPU対戦は [visual-redesign-verification.md](visual-redesign-verification.md)。
