# Issue #117 進捗

## 実装結果

- 対戦時間はドメインで一試合一度だけ +10 秒を許可し、通常の60秒から最大70秒までを shared wire、回転上限、残時間、結果判定へ整合させた。
- 受諾時は `RULE CHANGED`、`+10 SEC`、延長前後の時刻、専用SEを表示し、サーバー時刻は止めない。受諾台詞は「しょうがないな、10秒伸ばしてあげる。まだ諦めないでよ？」で、拒否には専用台詞を出す。
- GPT-Live の session に公式 client delegation を設定した。モデルが残り15秒以内で時間が必要と判断した場合だけ `session.delegation.created` を発行し、opaque な delegation ID と時刻を受信する。通常の字幕デルタ、ローカル VAD、固定正規表現からは判定を開始しない。
- delegation 到着後は転写の逆順到着に備えて150msだけ待ち、当該発話、直前会話、残時間、両者の残高を Responses API へ渡す。判定値は `accept_extension_10s`、`reject_extension`、`no_request` の三つに限定した。
- `no_request`、障害、タイムアウト、重複ID、古い Live 世代、終了後、残り15秒より前、延長済み、判定中の重複は時間を増やさず、延長枠も消費しない。確定した受諾・拒否だけがサーバーの domain guard を通る。
- 判定中は通常音声と字幕を抑制する。確定台詞は同じ delegation ID の `session.commentary.append` にキューし、抑制が終わった後に送るため、先行する通常返答が確定内容より後から漏れない。
- 残り15秒以内に20%でライバルが一度だけ延長を提案する。提案自体では延長しない。提案後1秒から5秒のサーバー有効窓内に Live が delegation した同意・拒否だけを同じ確定経路へ渡す。期限後の短い同意は受諾せず、新しい明示依頼だけを通常判定する。CPU対戦と AI 未接続時はこの処理を使わない。
- Live のゲーム文脈には、残り15秒以内かつ未使用なら「今この試合で未使用」「+10秒を一度だけ確定できる」「先に返答せず委任する」を明記し、それ以外は委任しない状態を渡す。
- 受諾済みでも直ちに時計を増やさず、確定台詞の終端後に `time_extension` を送る。音声のみはGPT側の900ms無音フェンス後にブラウザのPCM再生キュー完了ACKを待つ。映像付きは同じフェンスと、最後に送ったLiveAvatar `agent.speak` の `agent.speak_ended` の両方を待つ。0秒到達時は結果遷移だけを保留し、0秒以前の回転は通常どおり受け付ける。
- 音声の終端通知が来ない、音声・映像接続が失敗・終了する場合は、残った確定台詞を割り込みで止めてから15秒以内に延長を確定する。固定秒数待ちは通常経路には使わない。
- 音声のみは接続からの待機で試合時間を失わないよう、PLAY時に最低95秒ぶんの期限を再設定する。75秒以内にPLAYすると、70秒の延長試合、15秒の確定台詞フォールバック、結果8秒を170秒以内の終了処理開始枠に収める。既存の試合用GPT bridgeは期限を値で保持せず、更新後のサーバー期限を参照する。
- LiveAvatarは発行済みの120秒トークンをPLAY時に延長できないため、未開始を25秒で閉じ、短縮された試合を開始しない。audio/Avatarともロビー期限の非回復エラーを再接続ゲートに表示する。

## 未検証事項

- Live の commentary はモデルが言い換えるため、確定台詞と完全に同一の音声になる保証はない。サーバーの `time_extension` event と表示は確定値を維持する。
- 実ユーザーの発話認識精度、配信遅延、LiveAvatar の口形同期は実接続で確認が必要である。
- GPT-Liveには再生完了イベントがないため、音声のみは終端無音とブラウザの実再生キューを組み合わせた推定であり、物理スピーカーから聞こえる末尾の時刻を厳密には保証しない。LiveAvatarも `agent.speak_ended` はアバター側発話完了であり、視聴端末への配信遅延は別途残る。
- 今回の境界はfake clockとモックしたproviderで確認した。音声のみの170秒終了処理開始、LiveAvatarの120秒トークン、Vercel実行・外部プロバイダーが実際に同じ時刻まで接続を維持することは、この変更では実接続検証していない。
