# Issue #117 進捗

## 完了

- 音声字幕の日本語・英語の時間延長依頼を、残り15秒以下かつ1試合1回に限定して検出するようにした。
- Responses の判定には残時間、両者の残高、当該発話、直前会話を渡し、厳密な `accept_extension_10s` / `reject_extension` 以外と失敗・タイムアウトは拒否にした。
- 延長はドメインの一度だけ許可される +10 秒処理から反映し、60秒から70秒までの残時間、回転上限、wire検証、結果条件を整合させた。
- 判定中は通常のLive音声・字幕を遮断し、旧返答の無音境界または4秒上限後に既存の commentary 経路で確定台詞を発話するようにした。
- VM/View/CSS/GameAudio に `RULE CHANGED`、`+10 SEC`、延長前後の時刻表示、専用SEを追加し、開発用表示検収に受諾・拒否fixtureを加えた。
- `npm test`（288件）、`npm run typecheck`、`npm run lint`、`npm run check:server-runtime`、`npm run build` を実行した。
- Review #124 の修正として、発話途中の字幕デルタでは交渉を始めず、発話終了後に300msの字幕安定待ちを置いた。否定と残り時間の説明も依頼から除外した。
- 同一バッチ確認の追加修正として、15秒より前に終わった発話は、遅延字幕が届いても交渉待機・通常音声抑制を開始しないようにした。
- 実接続で「延長してください」は受理されたため、WebSocket接続や発話終了経路ではなく、自然な言い回しの不足が主因と判断した。`もっと時間伸ばして`、`もう少し時間ちょうだい`、`あとちょっとだけお願い`、`時間増やせる？`、`延長できる？` などを明示依頼として追加した。否定・時刻説明・単独の「お願い」は引き続き依頼にしない。
- 音声接続中の残り15秒以内に、1試合あたり20%でライバルが延長を提案する処理を追加した。提案の約1秒後から5秒間だけ明示同意を受け、同意時はモデル判定を介さずサーバーが +10 秒を確定する。拒否・無応答・CPU対戦では延長しない。
- 受諾台詞を「しょうがないな、10秒伸ばしてあげる。まだ諦めないでよ？」に変更し、表示検収へ「延長を提案」fixtureを追加した。
- `server/rivalBrain.test.ts`、`server/matchSession.test.ts`、`src/viewmodel/GameViewModel.test.ts` の focused test（108件）、`npm run typecheck`、`npm run lint`、`npm run check:server-runtime` を実行した。

## 未検証事項

- 実際のOpenAI Live接続で、commentary経路の確定台詞が指定文どおりに音声化されること。ローカルテストは旧通常返答を遮断して確定台詞をキューする順序までを検証している。
- 実ユーザーの発話認識精度、Live音声の配信遅延、LiveAvatarの口形同期はAPIキー・実接続環境での確認が必要。
- ユーザーが明示依頼をせず「もう間に合わない」「まだ負けたくない」のような困窮表現をした場合に、残り15秒の発話本文を Responses API へ意味分類のため送る拡張は未適用。自動承認レビューが、通常発話まで外部送信する明示許可が不足すると判断したため、ユーザーの明示承認待ちである。
